# P2 graphify (extractors, resolve, CLI to Go parity) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Port graphify-go v0.12.0 (35fcd9e) to `crates/graphify` so that, on the same corpus, graphify-rs writes the same `graphify-out/` bytes and the same command transcripts as graphify-go, and tag `go-parity-v0.12.0`.

**Architecture:** One Rust module per Go package (spec section 3), each file beside the Go file it ports, so a reviewer reads the two side by side. Every Go behaviour that Rust std does not give for free comes from `gostd` (Unicode 15 and 17, regexp, json, strconv, sort, pcg, toml, xml, csv, url, filepath, sha256), parse trees come from `gositter-rs`, and `--semantic` uses `bedrock`. Tests land before code in every module; a `graphify-parity` CI stage builds graphify-go from source and diffs both binaries' outputs on a fixed corpus that grows as each grammar's extractor lands.

**Tech Stack:** Rust 1.99.1, edition 2024, std only plus the workspace crates `gostd`, `bedrock` and the git dependencies `gositter` and `gositter-grammars` (`dobbo-ca/gositter-rs`, pinned by `rev`). Go 1.27.4 for the oracle build only.

**Spec:** `docs/superpowers/specs/2026-11-12-graphify-rs-design.md` (sections 3 to 7). Master plan: `docs/superpowers/plans/2026-11-12-graphify-rs-master.md`. Test map appendix: `docs/superpowers/plans/2026-11-13-p2-graphify-testmap.md`.

**Inputs read for this plan:** the spec, the master, gostd and bedrock plans; `crates/gostd/src` (the APIs below); gositter-rs `src/api.rs` and the runtime plan's "Public API"; the graphify-go 35fcd9e snapshot; the recon files `graphify-pipeline.md`, `graphify-deps.md`, `graphify-tests-parity.md`, `verify.md`, `inv/go.md`, `inv/verify.md`, `mapranges.txt` (where `verify.md` and the recon disagree, `verify.md` wins); `parity/DIVERGENCES.md`; `bd memories`.

## Review Focus

The five inputs most likely to break a user that no ported Go test pins down. Each has a test in the owning task.

1. **A file name that is not valid UTF-8** (`b"\xff.py"`). Go keeps it as a byte string; JSON writes one `EF BF BD` per bad byte (Go 1.27); text outputs print the raw byte. Rust: decision R3. Test: Task 15 `non_utf8_file_name`.
2. **Worker count.** Go output must not depend on GOMAXPROCS; ours must not depend on `available_parallelism`. Test: Task 20 `build_output_independent_of_workers` (the `testdata/extract` corpus built with 1 and 8 workers, `graph.json` bytes equal).
3. **A graph.json with a UTF-8 BOM.** `query.Load` strips it (`query.go:111`), `validate` does not (`validate.go:27`), so `validate` prints Go's decode error for the BOM. Test: Task 12 `validate_bom_error_text`.
4. **A label with more than 30 combining marks.** x/text inserts U+034F (CGJ) in NFKC and NFKD; it reaches `MakeID` and `norm_label`. Tests: Task 3 `make_id_cgj_run`, Task 11 `norm_label_cgj_run`.
5. **`hook install` with a binary path that holds a space, a quote, a non-ASCII and a control byte.** The hook text is `strconv.Quote` of `os.Executable()`. Test: Task 21 `hook_script_quotes_exe_path`.

**Port rules.**
- Go tests: every `func Test` is ported, or listed under "Not ported" in the module's `parity/README.md` block with a reason. Known: `prof_test.go` (3) asserts pprof files, ported as D-005 checks (no file written, exit 0); `code_test.go` asserts struct sizes with `unsafe.Sizeof`, ported as behaviour checks of the code tables only.
- Fuzz: the seeds of `FuzzCleanASCII` (idutil), `FuzzScanOldNodes` (export) and `FuzzRecvTail` (extract-resolve) become table tests in the tests PR; the code PR adds a cargo-fuzz target under `crates/graphify/fuzz/` to `fuzz.yml` once `graphify-rs-aa6.19` has landed it (else Task 23 adds the three targets).
- Upstream: a ported upstream test asserts graphify-go v0.12.0 behaviour. Where the upstream assertion differs from Go (node IDs by design, GOALS.md:83; any P3 backlog item), the case is not ported in P2 and is named in "Not ported" with its P3 bead if one exists. Python fixtures are copied to `crates/graphify/testdata/upstream/` with graphify's LICENSE beside them.
- **Ignore rule.** In a tests PR each test gets `#[ignore = "graphify-rs-ihc.<n>"]`, where `<n>` is the bead whose code PR makes it pass: for a test that parses several grammars, the bead of the last of them in the Order below. The appendix's "grammars named" column is the first guess; read each test. A code PR removes its own ignores and checks: `grep -rn 'ihc.<n>"' crates/graphify` prints nothing.

## Parity gate

```
graphify-go stage: git clone + checkout 35fcd9e (sha checked) -> go mod download + go mod verify
                   -> go build -mod=readonly ./cmd/graphify -> /out/graphify
graphify-rs-bin:   cargo build --release -p graphify -> /out/graphify
graphify-corpus:   pinned clones -> rm .git, graphify-out -> D-001/D-002 filter -> group filter
gate-go, gate-rs:  /usr/local/bin/graphify + /corpus/* + HOME=/home/gate -> run.sh -> /out
graphify-parity:   diff -r /go /rs (minus cache files) -> must be empty
```

It copies no repo file, so its BuildKit cache key is that SHA and nothing else. `parity/graphify/README.md` lists them:

The `graphify-corpus` stage copies `/corpus/<name>` from each `corpus-<name>` stage, then in this order: delete every committed `graphify-out`; **D-001/D-002 filter**: delete every file whose basename is an MCP config name (`.mcp.json`, `claude_desktop_config.json`, `mcp.json`, `mcp_servers.json`, `mcpconfig.go:19-22`) and where `jq` finds an `env` object with 2 or more keys, and every `pyproject.toml` that contains `tool.poetry`; **group filter**: delete every file whose lowercased extension (Go `filepath.Ext`) belongs to a group not listed in `parity/graphify/groups.txt`, and every extensionless file that starts with `#!` until all of `bash`, `python`, `js`, `ruby`, `php`, `lua` are listed (the groups `detect.ShebangExt` can route to); write `/corpus/MANIFEST` (`sha256sum` of every file, sorted) for the log. Groups are the extract task keys: `json`, `nogrammar`, `golang`, `python`, `js`, `java`, `csharp`, `c`, `cpp`, `hcl`, `rust`, `ruby`, `php`, `bash`, `scala`, `kotlin`, `julia`, `lua`, `zig`, `verilog`; their extensions are the `extract.go:251-305` dispatch (`.h` needs both `c` and `cpp`).

**Run** (`parity/graphify/run.sh <out>`, POSIX sh, runs only in CI): both sides have the binary at `/usr/local/bin/graphify` (`os.Executable()` is in hook scripts and `outfp`), the corpus at `/corpus/<name>`, `HOME=/home/gate`, `TZ=UTC`, `LC_ALL=C`, no `GRAPHIFY_*` or `GFY_*` variables. For each line of `parity/graphify/commands.txt` (`<n> <corpus> <args...>`, run with the corpus as working directory, optional `< <stdin file>`) it writes `<out>/t/<n>.stdout`, `<n>.stderr`, `<n>.exit`. Then it copies `/corpus/*/graphify-out` to `<out>/corpus/`. The command list covers, per corpus: `build`; `update` (the no-op path); `query` with a common label (pdqsort ties at `query.go:159`), an anchored pattern, and `(` (the regexp error text); `explain` of an ambiguous label, a path-qualified label and a hub (`query.go:215` ties); `path`, `path --undirected`, a pair with no path; `god-nodes`, `god-nodes --top 25 --json`; `affected` with 3 files, `--depth 1 --relation calls`, and `-` with stdin (`affected.go:140` ties); `diff` and `diff --json` of two corpora's `graph.json`; `validate` in a clean corpus and on 3 damaged copies (BOM, truncated, duplicate id: `validate.go:28` texts); `extract` of one file per enabled group; `ask` with 3 questions, `--dfs`, `--budget 500`, `--context <dir>` (D-004 holds on amd64 only; the gate is amd64); `export graphml`, `dot`, `csv`, `okf` (files land in `graphify-out`); `merge-driver` on 3 graph files; `serve` with a fixed JSON-RPC session on stdin (initialize, tools/list, each of the 8 tools); in a fresh `git init` repo `/hookrepo`: `hook install`, `hook status`, then `<out>/hook/` gets the 3 hook files, `.gitattributes` and `git config --get-regexp '^merge\.graphify'`. Not run: `watch` (D-003), `install` (writes under `HOME`, tested in Task 21), `save-result` (random name by design), `--semantic` (network).

**Wall time.** The job runs on main and `workflow_dispatch` only, and must finish in under 60 min (the ARC runners are shared). `run.sh` prints the elapsed seconds per corpus and per side; Task 23 reports the first run's times to the coordinator and drops or cuts a corpus (by subdirectory) if the total is over.

**Diff:** `diff -r --exclude=.graphify_cache.json --exclude=.graphify_stat.json --exclude=.graphify_root /go /rs`, except `nonutf8`, where only `graphify-out/graph.json` is compared (`cmp`). Any difference fails the stage; a difference is a Rust bug unless a D-id in `parity/DIVERGENCES.md` covers it, and then the corpus or the command list must avoid it (no output normalisation).

## PR cycle (every module task, 2 to 22 and 24 to 41)

Each task is two PRs. The task text gives only what differs.

**PR A, tests** (branch `port-<area>-tests-<4 hex>`):
- [ ] Claim the bead: `bd update <bead> --claim && bd dolt push`.
- [ ] Add the module's API with `todo!()` bodies: the task's **Interfaces** items plus every private item the ported tests name, under `#[allow(dead_code, unused_variables)]` on the module (removed in PR B), so the tests compile.
- [ ] Port the task's Go test files (appendix section of the task) to `src/<pkg>/tests/<stem>.rs` (R2), Go values copied verbatim, every test `#[ignore = "<bead>"]` by the Ignore rule. Port the task's upstream cases that hold for Go. Add the task's **Added tests**.
- [ ] Fill the module's block in `parity/README.md` (section "graphify against graphify-go (P2)"): source tests, ported, passing = 0, not ported with a reason.
- [ ] `cargo fmt`, commit, push, open the PR. Expected: `test` green (tests compile, ignored). Squash-merge.

**PR B, code** (branch `port-<area>-<4 hex>`):
- [ ] Implement the module from the Go files in the task. Remove this bead's ignores and the `allow`. Verify: `grep -rn '<bead>"' crates/graphify` prints nothing.
- [ ] Update the passing count in the module's block.
- [ ] `cargo fmt`, commit, push, PR. Expected: `test` green and the CI log lists the tests as `ok`. Squash-merge.
- [ ] Confirm `arm64`, `macos` and (from Task 23) `graphify-parity` are green on main. Then `bd close <bead> && bd dolt push` and report the PR to the coordinator.

**Interface rule.** Go `F` / `fooBar` become `f` / `foo_bar`; types keep their Go names. `(T, error)` becomes `Result<T, Error>` with the module's `Error` (R6). Go `string` is `String`/`&str` (R3), `int` is `i64`, `uint32` is `u32`, `[]T` is `Vec<T>`, `map` is `BTreeMap` (R4), `*T` that can be nil is `Option`. Paths for I/O are `&Path`. The **Interfaces** blocks list only what other tasks call.
